Summaries and Statistical Tests

You’ve already learned how to import data and make plots in R. Let’s now move further to data analysis. In this exercise, you’ll learn how to summarise a dataset numerically and run common statistical tests using simple R functions.

Data setup

We will reuse the same data we used for visualisation last week, viz_data.csv.

viz_data = readr::read_csv("data/viz_data.csv")
head(viz_data)
#> # A tibble: 6 × 8
#>      id group     site   height weight   bmi response outcome  
#>   <dbl> <chr>     <chr>   <dbl>  <dbl> <dbl>    <dbl> <chr>    
#> 1     1 High dose Site B   164    119.  44.1     62.1 Improved 
#> 2     2 High dose Site A   170.   130.  45.1     55.3 Improved 
#> 3     3 High dose Site B   175.   130.  42.7     59.1 Improved 
#> 4     4 Low dose  Site B   166    118.  42.7     65.9 No change
#> 5     5 High dose Site B   157.   117.  47.3     63.3 Improved 
#> 6     6 Low dose  Site B   160.   118.  46.3     60.6 Worsened

Common data summaries

Before jumping into formal tests, it’s always worth describing your data with some simple numbers. These are common measures of center and spread, the building blocks you’ll rely on for almost every analysis you do.

  • mean() gives you the arithmetic average of a numeric variable, a quick sense of where your data is “centred”.
  • median() gives you the middle value when the data is sorted, which is often more useful than the mean when your data has outliers (e.g., a few unusually high weight readings).
  • min() and max() return the smallest and largest values, handy for spotting data entry errors as much as for describing the variable itself.
  • quantile() splits your data into percentiles, so you can see, for example, the value below which 25% or 75% of observations fall.
  • sd() gives you the standard deviation, a measure of how spread out your values are around the mean.
mean(viz_data$weight)
#> [1] 120.3777
median(viz_data$weight)
#> [1] 120.15
min(viz_data$bmi)
#> [1] 35.4
max(viz_data$bmi)
#> [1] 54.8
quantile(viz_data$bmi)
#>     0%    25%    50%    75%   100% 
#> 35.400 42.350 44.400 46.725 54.800
sd(viz_data$bmi)
#> [1] 3.547647
  • cov() tells you whether two numeric variables tend to move together (positive), move in opposite directions (negative), or show no clear linear relationship (close to zero). Its exact value is hard to interpret on its own because it depends on the units of your variables.
  • cor() standardises this idea into a value between -1 and 1, making it much easier to interpret and compare across variable pairs.
cov(viz_data$height, viz_data$weight)
#> [1] 34.50298
cor(viz_data$height, viz_data$weight)
#> [1] 0.5827641

Common statistical tests

Now that you can describe your data, let’s move on to running some tests in R. You’ve already covered the logic behind these tests in your stats class, so here we’ll focus purely on how to actually call them in code and read what they give you back.

Association of two categorical variables

  • chisq.test() tests whether two categorical variables are associated with one another, by comparing observed counts in a contingency table to what you’d expect if the variables were independent.
  • fisher.test() answers the same underlying question, but uses an exact calculation rather than an approximation, which makes it more reliable when your contingency table has small cell counts.
group_outcome_table <- table(viz_data$group, viz_data$outcome)
chisq.test(group_outcome_table)
#> 
#>  Pearson's Chi-squared test
#> 
#> data:  group_outcome_table
#> X-squared = 1.7506, df = 4, p-value = 0.7815
fisher.test(group_outcome_table)
#> 
#>  Fisher's Exact Test for Count Data
#> 
#> data:  group_outcome_table
#> p-value = 0.7814
#> alternative hypothesis: two.sided

Difference between two groups

  • t.test() compares the means of a numeric variable between two groups, and assumes that variable is roughly normally distributed within each group.
  • wilcox.test() (which performs the Mann-Whitney test when comparing two independent groups) compares the distributions of a numeric variable between two groups without assuming normality, making it a useful backup when that assumption feels shaky.
t.test(response ~ group, data = viz_data, subset = group %in% c("High dose", "Low dose"))
#> 
#>  Welch Two Sample t-test
#> 
#> data:  response by group
#> t = 5.5122, df = 183.77, p-value = 1.186e-07
#> alternative hypothesis: true difference in means between group High dose and group Low dose is not equal to 0
#> 95 percent confidence interval:
#>   5.180856 10.957012
#> sample estimates:
#> mean in group High dose  mean in group Low dose 
#>                64.49444                56.42551
wilcox.test(response ~ group, data = viz_data, subset = group %in% c("High dose", "Low dose"))
#> 
#>  Wilcoxon rank sum test with continuity correction
#> 
#> data:  response by group
#> W = 6313, p-value = 3.315e-07
#> alternative hypothesis: true location shift is not equal to 0

ANOVA

  • aov() extends the idea behind the t-test to three or more groups, testing whether the means of a numeric variable differ across the levels of a categorical variable.
response_site_aov = aov(response ~ site, data = viz_data)
summary(response_site_aov)
#>              Df Sum Sq Mean Sq F value Pr(>F)
#> site          3    244   81.47   0.601  0.615
#> Residuals   296  40135  135.59

Functions in R: base vs. additional packages

Every function you’ve used so far in this chapter, like mean(), t.test(), and aov(), comes bundled with base R, meaning it’s available the moment you open RStudio with no extra installation needed. As you progress in public health analysis, you’ll also encounter functions from additional packages (installed with install.packages() and loaded with library(), just like you did with stringr last week) that extend what base R can do.

Accessing values from output objects

When you run a test like t.test() or chisq.test(), R doesn’t just print a result to your console. It actually creates a list-like object containing everything about that test, and the printed summary is just a friendly display of that object. Other functions, like summary(), return a named vector rather than a list. This matters because in your own code you’ll often want to pull out a single number (like a p-value or a specific summary statistic) to use later, rather than manually reading it off the printed output, and the way you extract that number depends on what kind of object you’re pulling it from.

  • str() lets you peek inside an output object to see what pieces of information it contains and how they’re named, and whether it’s a list or a vector.
  • The $ operator extracts one specific piece from a list-like object by name, once you know what it’s called.
  • [ and [[ let you extract by name or position from a named vector, which is what functions like summary() give you back instead of a list.
response_ttest = t.test(response ~ group, data = viz_data, subset = group %in% c("High dose", "Low dose"))

str(response_ttest)
#> List of 10
#>  $ statistic  : Named num 5.51
#>   ..- attr(*, "names")= chr "t"
#>  $ parameter  : Named num 184
#>   ..- attr(*, "names")= chr "df"
#>  $ p.value    : num 1.19e-07
#>  $ conf.int   : num [1:2] 5.18 10.96
#>   ..- attr(*, "conf.level")= num 0.95
#>  $ estimate   : Named num [1:2] 64.5 56.4
#>   ..- attr(*, "names")= chr [1:2] "mean in group High dose" "mean in group Low dose"
#>  $ null.value : Named num 0
#>   ..- attr(*, "names")= chr "difference in means between group High dose and group Low dose"
#>  $ stderr     : num 1.46
#>  $ alternative: chr "two.sided"
#>  $ method     : chr "Welch Two Sample t-test"
#>  $ data.name  : chr "response by group"
#>  - attr(*, "class")= chr "htest"

response_ttest$p.value
#> [1] 1.18611e-07
response_ttest$conf.int
#> [1]  5.180856 10.957012
#> attr(,"conf.level")
#> [1] 0.95
weight_summary = summary(viz_data$weight)

str(weight_summary)
#>  'summaryDefault' Named num [1:6] 98.5 115.5 120.2 120.4 125.5 ...
#>  - attr(*, "names")= chr [1:6] "Min." "1st Qu." "Median" "Mean" ...

weight_summary["Median"]
#> Median 
#> 120.15
weight_summary[[3]]
#> [1] 120.15

It’s tempting to guess the name of the value you want (e.g., typing $pvalue instead of $p.value), but R won’t warn you if you get it wrong. It will just silently return NULL. It’s also easy to try $ on something like the output of summary(), which will fail since that object is a named vector, not a list. Running str() first to check both the exact names and the type of object you’re dealing with will save you this frustration. :::
